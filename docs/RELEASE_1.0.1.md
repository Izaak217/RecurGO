# v1.0.1 发布核验记录

## 功能与范围

本版从 v1.0.0 的代码基线重建终局核对流程。终局使用当前节点已有的 KataGo
实时 ownership，不运行此前的棋形推断、置信度过滤或额外终局搜索。
此前已公开的 v1.0.1 由本版替换；Git 历史保留，发布标签指向本版最终源码。
面向用户的发布说明见[版本记录](../CHANGELOG.md)。

数据流为当前节点分析结果 → `ScoringDialog` 快照 → `live_assignments` →
用户逐点核对 → `score_ownership` → 棋谱库 `scoring_json` 和结果字段。
打开终局窗口后，后续分析回调不会覆盖人工修改；返回棋局恢复正常分析流程。

- 初始黑白归属沿用局内显示的 `0.08` 阈值，实时图中没有黑白标记的点保留待确认。
- 用户可逐点指定黑、白、双方各半或待确认，也可整块标记／恢复死子。
- 双方共有空点每方计半子；胜差沿用中国围棋规则的子数表示，保留四分之一子精度。
- 不根据 AI 的接近零数值自动判定双方共有。劫争、双活和未终局的争议仍需核对。
- 死子默认隐藏，开启显示后淡化呈现；切换显示不改变归属或计分。
- 待确认点使用空心小方框。确认按钮上方持续显示禁用原因和处理方法，解决后消失。
- 归属、死子与结果可保存和重开；无效存档不参与计分，保留原记录结果供查看。
- KataGo 模型、分析预算、候选排序、全盘复盘和“最强”陪练配置未修改。

## 正式构建和发布步骤

1. 将已确认的功能和说明定稿，统一源码及安装器版本为 `1.0.1`，运行上述源码检查。
2. 从最终源码运行 `scripts/build_windows_release.py`，生成全新的构建目录。
   不覆盖旧测试包，也不将开发版安装程序改名。
3. 检查正式包的文件清单、SHA-256、编译模块与源码一致性、第三方许可及隐私排除项。
   从待安装目录运行环境检测和冻结程序，使用项目内的隔离数据与缓存目录。
4. 保存旧发布的元数据及已核对哈希的本地附件，确认正式包检查通过后再替换旧发布。
   将源码快进推送到主分支，按已确认的替换范围更新 `v1.0.1` 标签。
5. 用已确认的完整中英文文案创建发布草稿，上传安装程序和 `SHA256SUMS.txt`。
   核对 GitHub 返回的文件大小及 SHA-256 后公开；不上传整个构建目录。
6. 再次核对发布文案、主分支、标签、附件、最新正式发布状态，以及 v1.0.0 未变。
   每次构建的详细清单、探针输出、哈希和发布回读结果留在本地对应的 `build/release-*`
   目录中，实际发布状态以 GitHub Release 为准。

## 使用与验证边界

同为 v1.0.1 的旧安装包不会自行更新，安装本版需重新下载安装程序；可用 SHA-256
区分附件。升级前关闭旧程序并备份 `%LOCALAPPDATA%\RecurGO`；如设置了
`RECURGO_DATA_DIR`，以该目录为准。程序目录和棋谱数据目录相互独立。

当前节点尚无实时领地时，用户需要手动指定，或返回允许实时分析的模式中等待分析。
连续停一手产生的新节点也可能尚无结果；数子窗口不借用上一节点的归属。
本版没有新增公平对战中的实时分析，也没有对循环劫等特殊裁定作自动判决。
终局图与局内图一致仅代表采用相同数据和显示阈值，最终结果仍以用户核对为准。

测试包的安装体验由用户验证；正式包重新构建后须独立检查其冻结程序和清单。
本次不将某台设备的成功探针扩大为所有显卡、系统或全部功能的兼容性承诺。
